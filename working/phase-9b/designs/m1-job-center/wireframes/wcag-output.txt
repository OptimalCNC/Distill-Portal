Phase 9b Job Center contrast — expected results
================================================

This file is intended to capture the output of running
`python3 wcag.py` from the sibling directory. The script computes
WCAG 2.1 contrast ratios for every new visible foreground/background
pair the Phase 9b Job Center introduces.

How to (re)generate this file
-----------------------------

    python3 working/phase-9b/designs/m1-job-center/wcag.py \
        > working/phase-9b/designs/m1-job-center/wireframes/wcag-output.txt

Expected outcome
----------------

ALL 39 pairs MUST pass their applicable WCAG bar in BOTH light and dark
modes. The expected verdict is `Light failures: 0  Dark failures: 0`
with the final line reading:

    ALL pairs pass their applicable WCAG bar in BOTH light and dark.
    Phase 9b Job Center may ship at AA on every new surface.

If the script reports any failure, design adjustment is REQUIRED before
M2 implementation begins. Likely culprits and remediations:

  - Pill text mix at 75% / ink reads too light against the 10-12% fill on
    dark mode → bump the text mix to 85% / ink (still no new token).
  - Cancel button border at 35% / border reads under 3.0:1 on light mode
    → swap to 35% / surface (matches the pill recipe).
  - Dashed-border pairs (cancel_requested, interrupted) can lose
    perceptual contrast when the dash spacing exceeds the border width
    → keep border-width 1px, stroke-dasharray default (browser-managed).

Why this file is a stub instead of a captured run
-------------------------------------------------

The artifact-producing environment for this dispatch could not execute
`python3` due to an upstream tooling outage at write time. The script
itself is byte-equivalent in pipeline to Phase 7c's wcag.py (which has
been run + verified) and uses the same canonical M2a token values. The
reviewer is asked to run the script in their own environment to confirm
the table; the structure below is the format that will be captured.
