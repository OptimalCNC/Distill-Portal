   573	## 5. Timestamp display
   574	
   575	Spec anchor: `working/phase-5.md:713`.
   576	
   577	> "Each message panel carries a timestamp display: relative time as
   578	> visible label (`relativeTimeFrom(now, msg.timestamp)`), absolute ISO
   579	> via `<time dateTime='…'>` and on `title=` hover. Timestamps with
   580	> `null` value render as '—' (preserved from Phase 4 contract)."
   581	
   582	### 5.1 The `<time>` element
   583	
   584	```tsx
   585	function MessageTime({ iso, now }: { iso: string | null; now: string }) {
   586	  if (iso === null) {
   587	    return <time>—</time>;
   588	  }
   589	  const rel = relativeTimeFrom(now, iso);
   590	  return <time dateTime={iso} title={iso}>{rel}</time>;
   591	}
   592	```
   593	
   594	- Visible text: the relative-time label (e.g. "3 minutes ago", "2
   595	  days ago"). Computed via `relativeTimeFrom(now, iso)` which is
   596	  already wired in Phase 4 / M2b.
   597	- `dateTime={iso}` attribute: the absolute ISO 8601 string.
   598	  Machine-readable for browser tooltips, copy-paste, screen readers,
   599	  and search-engine indexing.
   600	- `title={iso}` attribute: the absolute ISO string also surfaced on
   601	  hover (browser default tooltip).
   602	- Null: a single em-dash character (U+2014) inside a `<time>` with no
   603	  `dateTime` attribute. Rendering still uses the `<time>` shell so
   604	  the surrounding CSS (which targets `time` with the muted-italic
   605	  rule) treats null timestamps consistently.
   606	
   607	### 5.2 No timestamp on boundary messages
   608	
   609	Per Q7 in m4-plan §5, boundary messages do NOT carry a `<time>`. The
   610	chapter-break treatment is editorial. The user message that follows
   611	the boundary carries its own timestamp, giving the chronological
   612	signal where the user expects it.
   613	
   614	### 5.3 Where timestamps appear
   615	
   616	Timestamps render INSIDE the attribution row (`.msg-attr`) for
   617	`user`, `assistant`, `tool_use`, `tool_result`. They do NOT render on
   618	`system` (single-line muted prose; timestamp would clutter), `boundary`
   619	(editorial), or `unknown` (fallback diagnostic; no useful chronology).

   627	> "If `parsed.truncated`, a small banner at the top of the Transcript:

   637	
   638	The "Open raw" word is bolded text only — there is NO anchor element
   639	embedded inside the banner. The banner copy is a **reference** to the
   640	"Open raw" anchor that lives in the session header (see §6.1.1 below).

   652	### 6.1.1 Session header expansion in M4 (BLOCKING-2 resolution)
   653	
   654	Spec line 626 enumerates "Open raw" as a session-header element. M2b
   655	shipped a minimal header without it (deferred). The truncation banner
   656	copy at spec line 715 is load-bearing — it points users to a
   657	session-header anchor that does NOT yet exist. Round-2 coordinator
   658	resolution: M4 scope EXPANDS to include landing the "Open raw" anchor
   659	in the session header.
   660	
   661	**Where it lands.** `apps/frontend/src/features/sessions/SessionView.tsx`
   662	header. The header currently renders title + tool badge + status pill
   663	+ conflict badge from M2b; M4 appends "Open raw" to the right-side
   664	action group, AFTER the conflict badge.
   665	
   666	**Visibility rule.** Visible only when `row.storedSessionUid !== null`
   667	(matches `SessionMetadata.tsx`'s "View raw" anchor visibility rule
   668	from M2b). When the row is source-only (`storedSessionUid === null`),
   669	the anchor is omitted entirely — it would 404 anyway, and the
   670	truncation banner only fires for parsed sessions which by definition
   671	have a stored UID.
   672	
   673	**Anchor copy.** `Open raw` — verbatim per spec line 626. NOT "View
   674	raw" (which is the Metadata-tab precedent); the spec uses "Open raw"
   675	specifically for the header position to differentiate from the
   676	Metadata tab's variant.
   677	
   678	**Anchor URL.** `/api/v1/sessions/${row.storedSessionUid}/raw` via the
   679	existing `RAW_SESSION_PATH` builder in `apps/frontend/src/lib/api.ts`.
   680	Reuses the same path as Metadata's "View raw"; the difference is the
   681	copy and the position, not the destination.
   682	
   683	**Anchor attributes.** `target="_blank"` + `rel="noreferrer"` —
   684	matches the Phase 4 pattern at `SessionMetadata.tsx`. No `download`
   685	attribute (the user inspects the raw payload in a new tab; downloading
   686	is opt-in via the browser's UI).
   687	
   688	**Position.** Right-side action group of the session header, AFTER the
   689	conflict badge. The order top-to-bottom (in the flex row): title (left
   690	flex-grow), tool badge (left), then on the right: status pill →
   691	conflict badge → "Open raw".
   692	
   693	**Typography.** `--font-chrome --text-sm`. Color `--color-accent` (link
   694	styling per the existing "View raw" precedent at `SessionMetadata.tsx`).
   695	Hover: underline. Focus-visible: 2 px accent outline + 2 px offset.
   696	
   697	**State variants.** Hidden when `state === "no_raw"` (anchor would 404
   698	since `storedSessionUid` is null). Visible otherwise (`success`,
   699	`truncated`, `loading`, `error`, `idle`). The anchor's position in the
   700	header is structural — it does not jump around as state changes.
   701	
   702	**Truncation banner relationship.** When `state === "truncated"` the
   703	"Open raw" anchor in the header IS the destination the banner copy
   704	points to. They co-render: banner in the transcript top, anchor in
   705	the session header. The user follows the prose hint "Use the Open
   706	raw anchor in the session header" → eye flies up to the header →
   707	clicks the anchor → opens raw payload in new tab.
   708

   710	m4-plan.md is frozen for this design loop): the developer's modified
   711	files list at m4-plan §3 must be expanded to include
   712	`apps/frontend/src/features/sessions/SessionView.tsx` (for the header
   713	anchor) and `apps/frontend/src/features/sessions/SessionView.test.tsx`
   714	(for a regression test that asserts the anchor renders when
   715	`storedSessionUid !== null` and is omitted when null). The CSS
   716	modifications belong in `SessionView.css` (existing per-component
   717	sibling). Reuse existing tokens; no new token additions for this
   718	expansion.

   720	### 6.2 Visual recipe
   721	
   722	- **Container.** `<div class="transcript-banner transcript-banner-truncation"
   723	  role="status">`. The `role="status"` makes screen readers announce
   724	  the banner without interrupting; assistive tech treats it as a
   725	  polite live region.
   726	- **Background.** `color-mix(in srgb, var(--color-warn) 8%, var(--color-surface))`.
   727	  A warm wash; reads as a soft warn tint without screaming.
   728	- **Inline-start stripe.** `border-inline-start: 3px solid var(--color-warn)`.
   729	  3 px is the SC 1.4.11 non-text bar; the warn color holds against
   730	  surface (pair B02 in colors.md).
   731	- **Padding.** `var(--space-3) var(--space-4)` (12 px / 16 px).
   732	- **Border-radius.** `var(--radius-sm)`.
   733	- **Typography.** `--font-chrome --text-sm --color-ink`. Body weight.
   734	  `<strong>Open raw</strong>` carries `font-weight: 600` (the chrome
   735	  bold weight).
   736	- **Margin-bottom.** `var(--space-6)` (24 px) to separate from the
   737	  warnings banner (if both present) or the first message.

   740	
   741	- **Property.** `opacity` ONLY (NOT `background-color`, NOT `transform`).
   742	- **Duration.** `var(--motion-base)` (120 ms).
   743	- **Easing.** `var(--ease-out)`.
   744	- **Trigger.** `parsed.truncated` becomes true → component mounts.
   745	- **Implementation.** `animation: transcript-banner-fade
   746	  var(--motion-base) var(--ease-out) both;` where:
   747	
   748	  ```css
   749	  @keyframes transcript-banner-fade {
   750	    from { opacity: 0; }
   751	    to   { opacity: 1; }
   752	  }
   753	  ```
   754

   757	duration via the global rule.

    16	## 1. Brief
    17	
    18	**M4 is the chunk where the right pane finally speaks.** M2a landed
    19	the language (Fraunces, oklch ramp, motion tokens, noise overlay).
    20	M2b landed the chrome (tab strip + minimal header + Metadata + Raw +
    21	two placeholders). M3a / M3b landed the silent machinery (parsers,
    22	useParsedSession, cacheEpoch). M4 is the chunk where parsed messages
    23	become readable text on the screen.
    24	
    25	The Transcript tab is the **default landing surface from M4 onward**
    26	(per Resolved Decision #11): on every fresh selection, the user lands
    27	here unless they were on a different tab when the previous selection
    28	finished. So this surface carries the first-impression weight for
    29	every session click. It must read as quiet, finished, editorial — not
    30	chatty, not chunky, not loud. Six restraints carry the weight:
    31	
    32	1. **Ink-on-paper rhythm.** Reading content lives at 70ch with
    33	   comfortable leading. Messages stack vertically with a
    34	   three-magnitude rhythm: 16 px default between any two adjacent
    35	   messages, 24 px override between adjacent same-kind messages
    36	   (user→user, assistant→assistant, etc.), and 32 px around chapter
    37	   breaks (boundary messages). The scroll surface reads like a printed
    38	   transcript, not a chat log.
    39	
    40	2. **One tint, used surgically.** User messages carry a 5 % accent
    41	   tint over the surface (mirrors the selected-row recipe — same
    42	   recipe, different surface). Assistant messages sit on the bare
    43	   warm-paper surface. The tint differential IS the user/assistant
    44	   discrimination. No avatars. No icons. No labelled rails.
    45	
    46	3. **The chapter break as page furniture.** Boundary messages
    47	   render as a full-width 1 px hairline with a centered Fraunces
    48	   italic small-caps label ("SESSION RESUMED" / "CONVERSATION
    49	   COMPACTED"). 32 px breathing on either side. This is signature
    50	   detail #1 from §Design Language; M4 is the chunk that lands it
    51	   first (M5's Skim view will reuse the recipe verbatim).
    52	
    53	4. **Banners that whisper, not shout.** The truncation banner
    54	   carries a 3 px warn stripe on the inline-start edge plus an 8 %
    55	   warn-tinted background. It does NOT carry an icon, an emoji, or a
    56	   close button. The parse-warnings banner is a `<details>` element
    57	   that disappears entirely when dismissed; warnings re-arrive on
    58	   next session selection per spec.
    59	
    60	5. **Tools fold quietly.** `tool_use` and oversized `tool_result`
    61	   messages collapse behind native `<details>` disclosures with the
    62	   spec's exact summary copy ("Arguments", "Expand (N more bytes)").
    63	   The `<pre>` blocks sit on `--color-surface-raised` so they read
    64	   as machinery — distinct from the body prose without being loud.
    65	
    66	6. **Timestamps as marginalia.** The relative-time label is the
    67	   visible affordance; the absolute ISO is the `dateTime` attribute
    68	   plus the `title` hover tooltip. Null timestamps render as a
    69	   single em-dash. Timestamps NEVER appear on boundary messages —
    70	   the chapter break is editorial, not chronological.
    71	
    72	The aesthetic vision: a returning user opens a session, sees the
    73	right pane fade in, and reads the conversation the way they would
    74	read a printed memo. The left rail of subtle accent tint marks user
    75	turns. Tools collapse inside disclosures — present but not
    76	demanding. The chapter break, when it appears, slows the eye for a
    77	breath. Banners advise without interrupting. There is no chrome
    78	between the user and the words.

   115	
   116	The TranscriptView tree is a single state-discriminator at the top
   117	followed by a flat per-kind render. No nested feature components, no

   122	<TranscriptView row={row} now={now}>

   132	            └── <ol class="transcript-stream">
   133	                 ├── (messages.length === 0) → <li class="transcript-empty-stream">…</li>
   134	                 └── messages.map(msg => <MessageRow msg={msg} now={now} />)
   135	                      ├── kind="user"        → <UserMessage />
   136	                      ├── kind="assistant"   → <AssistantMessage />
   137	                      ├── kind="tool_use"    → <ToolUseMessage />
   138	                      ├── kind="tool_result" → <ToolResultMessage />
   139	                      ├── kind="system"      → <SystemMessage />
   140	                      ├── kind="boundary"    → <BoundaryMessage />

   169	### 2.3 The keep-mounted contract
   170	
   171	TranscriptView's React subtree carries **no `key=` on its root**. Per
   172	M2b's Resolved Decision #12 (spec lines 650-658), tab switches must
   173	NOT remount the panel content. The only natural state-reset point is
   174	a `selectedRowKey` change, which is handled at the SessionView layer
   175	via `<SessionView key={selectedRowKey}>`.
   176	
   177	Component-local state that persists across tab switches:
   178	
   179	- `warningsBannerDismissed` (`useState<boolean>`).
   180	- Native `<details>` open/closed state (browser-managed; survives
   181	  reparenting because the element instance is stable).
   182	- Scroll position (browser-managed; survives `display: none` toggles).
   183	
   184	Defensive belt-and-suspenders:
   185

   196	`<MessageRow key={msg.messageIndex} />` — that's content keying, not

    51	
    52	### Surface 1 — Truncation banner appearance
    53	
    54	CSS `@keyframes` on `.transcript-banner-truncation`. The banner is
    55	mounted by the React renderer when `state === "truncated"`; the
    56	animation fires automatically on first paint:
    57	
    58	```css
    59	.transcript-banner-truncation {
    60	  /* Static visual recipe — colors and layout, no animation. */
    61	  background: color-mix(in srgb, var(--color-warn) 8%, var(--color-surface));
    62	  border-inline-start: 3px solid var(--color-warn);
    63	  border-radius: var(--radius-sm);
    64	  padding: var(--space-3) var(--space-4);
    65	  color: var(--color-ink);
    66	  font: var(--text-sm) / var(--leading-comfortable) var(--font-chrome);
    67	  margin-block-end: var(--space-6);
    68	
    69	  /* Animation — opacity ONLY. */
    70	  animation: transcript-banner-fade var(--motion-base) var(--ease-out) both;
    71	}
    72	
    73	@keyframes transcript-banner-fade {
    74	  from { opacity: 0; }
    75	  to   { opacity: 1; }
    76	}
    77	```
    78	
    79	The `animation-fill-mode: both` keeps opacity at 1 after the keyframe
    80	completes (matches M2b's `tab-fade-in` pattern at `SessionView.css`).
    81	On the FIRST mount of `<TruncationBanner>` (e.g. when state
    82	transitions `loading → truncated`), the keyframe fires; on subsequent
    83	re-renders inside the same mount, the property string doesn't change
    84	and the keyframe doesn't re-fire. This is correct: the banner appears
    85	once per truncation.
    86	
    87	**The animation explicitly targets `opacity` and ONLY `opacity`.**
    88	The static visual recipe (background, border, padding, color) is set
    89	at component mount via the static `.transcript-banner-truncation`
    90	selectors above; the static colors are NOT interpolated in.

    93	
    94	Native `<details>` element + a global CSS rule already in place from

   100	  :root {
   101	    interpolate-size: allow-keywords;
   102	  }

   137

   139	- `transition: border-color …`
   140	- `transition: width …`
   141	- `transition: height …`
   142	- `transition: top …`
   143	- `transition: padding …`
   144	- `transition: margin …`

   146	- `transition: letter-spacing …`

   152

   277	 * macOS / iOS) so the swap is invisible — line heights stay within
   278	 * 1 px on every step in the type scale. Designer-recommended starting
   279	 * values per design.md §"Fraunces fallback math"; revisit after the
   280	 * M6 manual font-swap measurement.
   281	 *
   282	 * Reversibility (Resolved Decision #15): deleting both @font-face
   283	 * blocks AND the two woff2 files yields a still-cohesive
   284	 * system-serif aesthetic. No font is required for the page to
   285	 * render. */
   286	/* unicode-range narrowing rationale (M2a developer): design.md item 12
   287	 * lists `U+0000-007F, U+00A0-00FF, U+2000-206F` as the subset coverage.
   288	 * The implemented ranges below tighten that:
   289	 *   - `U+0020-007E` instead of `U+0000-007F` — strips ASCII control
   290	 *     characters (NUL through US, plus DEL) which are non-printing and
   291	 *     never appear on the inspection surface. Trims the @font-face
   292	 *     glyph-table hint without affecting any visible glyph.
   293	 *   - `U+2010-2027, U+2030-2052` instead of `U+2000-206F` — keeps the
   294	 *     General Punctuation glyphs Fraunces actually renders (en/em-dash,
   295	 *     hyphenation point, primes, ellipsis, per-thousand sign,
   296	 *     letterlike-numerals slash) and drops the `U+2028-202F` line/word
   297	 *     separator + bidi-control range plus `U+2053-206F` deprecated
   298	 *     swung-dash + invisible-format range. Subset script's actual glyph
   299	 *     emission already excludes those — the unicode-range here matches
   300	 *     the subset content rather than overstating coverage.
   301	 * The browser uses unicode-range to skip downloading the woff2 if no
   302	 * code-point in the page falls inside the declared range; tightening
   303	 * keeps the swap behaviour deterministic. */
   304	@font-face {
   305	  font-family: "Fraunces";
   306	  font-style: normal;
   307	  font-weight: 100 900;
   308	  font-display: swap;
   309	  /* Dual format() hint: `woff2-variations` is the technically-correct
   310	   * MIME hint for variable-axis woff2 (per CSS Fonts L4 §"font-format"),
   311	   * BUT every Chromium/Safari/Firefox build that ships oklch() also
   312	   * accepts a plain `format("woff2")` for variable fonts. The dual
   313	   * declaration is progressive enhancement: a future browser that
   314	   * strict-parses `woff2-variations` (skipping the second hint) loads
   315	   * exactly once; today's browsers fall through to the second `format`
   316	   * and load exactly once. Either way the fetch count stays at one. */
   317	  src: url("/fonts/Fraunces-subset.woff2") format("woff2-variations"),
   318	    url("/fonts/Fraunces-subset.woff2") format("woff2");
   319	  size-adjust: 99.5%;
   320	  ascent-override: 92%;
