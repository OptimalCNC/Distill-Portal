- Backend owns machine-consumable HTTP routes; do not reintroduce backend-owned end-user HTML.
- Frontend talks to the backend only over HTTP and only consumes generated contract types from `components/ui-api-contracts/bindings/*.ts`.
- `apps/frontend` must not import from `components/collector-runtime`, `components/ingest-service`, or `components/raw-session-store`.
- HTTP payload changes must update `components/ui-api-contracts`, the Rust and TS sides of both apps, and relevant tests together.

    47	## Idiom details
    48	
    49	### Surface 1 — Tab indicator slide
    50	
    51	Single absolutely-positioned `<span class="indicator">` inside the
    52	tablist. Its `transform: translateX(...) scaleX(...)` is computed from
    53	the active tab's `getBoundingClientRect()` and applied imperatively
    54	on activation. The transition only animates `transform` (compositor-
    55	cheap; no layout reflow):
    56	
    57	```css
    58	.tabs .indicator {
    59	  position: absolute;
    60	  bottom: -1px;
    61	  left: 0;
    62	  width: 1px;                /* base extent — load-bearing, see below */
    63	  height: 1px;
    64	  background: var(--color-accent);
    65	  transform-origin: left;
    66	  transform: translateX(0) scaleX(0);
    67	  transition: transform var(--motion-base) var(--ease-standard);
    68	  pointer-events: none;
    69	}
    70	```
    71	
    72	The `width: 1px` is load-bearing: an empty absolutely-positioned
    73	`<span>` resolves to `width: auto` (= 0), and `scaleX(N) × 0 = 0`
    74	would render an invisible indicator. With the 1 px base, the JS-
    75	written `transform: translateX(${x}px) scaleX(${tabRect.width})`
    76	grows the indicator to the active tab's measured pixel width.
    77	
    78	On initial mount the indicator settles via `requestAnimationFrame`
    79	so font-swap metrics shifts (Fraunces fallback per M2a §4) don't
    80	strand the indicator off-target.
    81	
    82	### Surface 2 — Tab panel cross-fade-IN
    83	
    84	CSS animation-name re-trigger on the panel's own
    85	`<div role="tabpanel">` element. The panel's React subtree is
    86	**STABLE** across tab switches (Resolved Decision #12 / spec lines
    87	650–658 require visited panels to stay React-mounted so RawTab's
    88	`consumeRawPreview` consumer keeps streaming and so M3+
    89	`useParsedSession` results are not recomputed on every flip). The
    90	keyframe is defined once at module scope:
    91	
    92	```css
    93	@keyframes tab-fade-in {
    94	  from { opacity: 0; }
    95	  to   { opacity: 1; }
    96	}
    97	```
    98	
    99	The panel toggles its inline `animation` style based on `isActive`:
   100	
   101	```jsx
   102	<div role="tabpanel"
   103	     hidden={!isActive}
   104	     id={`panel-${tabId}`}
   105	     aria-labelledby={`tab-${tabId}`}
   106	     tabIndex={isActive && (tabId === "skim" || tabId === "transcript" || tabId === "raw") ? 0 : undefined}

   109	                          : "none" }}>
   110	  {/* STABLE content — never remounted on tab change */}
   111	</div>
   112	```
   113	
   114	The browser fires the keyframe each time the inline `animation`
   115	property string changes from `"none"` to a real animation. Active →
   116	active re-renders DON'T re-fire (the property string is unchanged).
   117	`animation-fill-mode: both` ensures opacity stays at 1 after the
   118	animation completes. Outgoing panel hides instantly via the `hidden`
   119	attribute (display: none) — no fade-out.
   120	
   121	**Do NOT use a React `key={activeTab}` on the panel content** —
   122	that would unmount + remount the subtree on every tab change,
   123	aborting in-flight work and breaking the keep-mounted contract.
   124	Codex round 3 caught the previous artifact draft regressing to
   125	`key={activeTab}`; the corrected mechanism above does NOT touch the
   126	React tree on tab change.
